Признаки атаки

Детектор ищет в сообщении клиента типичные приёмы, которыми пытаются перехватить управление ботом, а в ответе модели — фрагменты её правил. Сработавшие признаки видны в колонке Признаки атаки.

Что происходит с подозрительным сообщением

  • Клиент получает обычный ответ модели: от взлома бота защищают его правила и проверки ответа, а не детектор. Исключение — ответ с фрагментами правил: его заменяет нейтральная фраза.
  • Сообщение и ответ не сохраняются в {{ section_link('chat-message') }}, поэтому атака не накапливается в памяти бота.
  • Администратор получает в Telegram уведомление «Внимание: подозрительное сообщение…» — не чаще раза в 15 минут на одного клиента, чтобы атакующий не завалил его сообщениями.

Как разобрать подозрительное сообщение

  1. В блоке Фильтры выберите Подозрительное → Да.
  2. Откройте запись значком глаза. Сравните Ответ модели и Отправлено клиенту: если они отличаются, бот заменил опасный ответ.
  3. Посмотрите другие сообщения клиента: фильтр Chat ID здесь или в {{ section_link('chat-message') }}.
  4. Если попытки повторяются — нажмите Заблокировать клиента рядом с Chat ID на странице записи и подтвердите. Там же клиента можно разблокировать.

Новые события без перезагрузки

Пока журнал открыт, он раз в 15 секунд проверяет новые записи. Над таблицей появится плашка «Новых событий в журнале: N»; если среди них есть подозрительные, плашка станет жёлтой и покажет их число. Нажмите Показать, чтобы обновить список.

{% call note("warning", "Детектор — сигнал, а не защита") %} Детектор работает по шаблонам фраз: атакующий может перефразировать, а обычный клиент — случайно написать похоже на атаку. Ничего не блокируйте только из-за одной отметки. Встроенные шаблоны задаёт разработчик; если заметили новый приём, который детектор пропускает, передайте пример разработчику. {% endcall %}

Сколько хранится журнал

Столько дней, сколько указано в {{ section_link('bot-config') }} → Хранить журнал, дней (по умолчанию 90). Бот удаляет старые записи при запуске и затем каждые 6 часов. Расходы при этом не теряются: итоги по дням остаются в {{ section_link('usage-daily') }}.
