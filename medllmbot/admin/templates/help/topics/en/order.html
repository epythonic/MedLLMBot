How the bot answers about an order

A customer asks “where is my order?”. The bot asks for the order number and the last 4 digits of the phone number the order was placed with, and looks the order up here. If the number and the digits match, the client learns the status, items, total and expected date. If not, the bot replies that the order was not found and does not say what exactly did not match.

  • For the check the bot asks only for 4 digits, not the whole phone number, so a question about an order does not turn into a lead. A lead appears if the client writes the full number themselves.
  • Brute-force protection: after 5 failed checks in an hour from one chat, or 10 for one order from all chats, the bot stops checking and offers to leave a phone number so that a manager calls back. The counters are kept in the bot's memory and reset when it is restarted or updated.
  • A mistyped number that does not look like an order number is not sent to the system and does not count as an attempt.
  • What the bot checked and with what result is shown in {{ section_link('audit-event') }}, in the What the bot searched for field: «order_status DE-10023 → Передан в доставку» (“handed over for delivery”) or «→ телефон не совпал» (“phone did not match”).
  • The section works in the “Electronics store” profile. The dental clinic has no orders, and the bot does not look them up.

How to manage orders

  • Change the status: the pencil icon in the order row → Status → Save. The bot gives the new status from the next question.
  • Add an order: the + New Order button. The number must be unique.
  • Delivery date — the expected date. If it has moved, correct it: the client hears what is written here. An empty date means the bot will say that a manager will confirm it.
  • Items — without prices: the bot names the order total, and the price of an individual item that is not in the catalog is replaced by the price check with “I'll check the price”.
